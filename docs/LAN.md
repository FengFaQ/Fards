# LAN.md — 局域网双人对战使用说明

Fards 支持**同一局域网内两名玩家互相对战**（不是打 AI，也不依赖任何公网服务器）。
房主在自己电脑上跑一个极小的局域网服务器，访客用浏览器连上来即可。

```
 房主浏览器（跑规则引擎，权威端）
        │  ws://<房主IP>:8080/ws
        ▼
 ┌────────────────────────────┐
 │  node server/lan-server.mjs │   只做三件事：
 │  ① 托管 dist/ 静态站点      │   房间 / 消息中转 / 静态文件
 │  ② WebSocket 房间与中转      │   ❗不跑规则引擎、不存对局
 │  ③ /healthz 健康检查        │
 └────────────────────────────┘
        ▲  ws
        │
 访客浏览器（只渲染房主下发的脱敏视图，发送指令）
```

对局规则由**房主浏览器**执行（host 权威）：房主持有完整 `GameState`，把对手不该看到的
信息（手牌内容、牌库顺序、盖牌、随机种子、私有计数器）脱敏后再下发给访客。
服务器只搬运 JSON，因此不需要在服务器上跑 TypeScript 引擎，也没有数据库。

---

## 1. 前置条件

- **Node.js ≥ 20**（开发用 24；`npm run lan` 只用到内置模块 + `ws`）
- 两台设备在**同一个局域网**（同一 Wi-Fi / 同一路由器 LAN 口）
- 房主先完成一次构建（产物在 `dist/`）：

```bash
npm install
npm run build
```

## 2. 房主步骤（创建房间）

1. 启动局域网服务器（**默认端口 8080，托管 `dist/`**）：

   ```bash
   npm run lan
   ```

   等价于 `node server/lan-server.mjs`。启动后会打印（IP 已按「物理网卡优先」排序，
   虚拟网卡/VPN 单独列在后面，一般不用发给访客）：

   ```
   ================================================================
     Fards 局域网对战服务器
   ================================================================
     版本      : v1.0.0（协议 v1，WS 后端：ws）
     静态目录  : C:\...\Fards\dist
     监听      : 0.0.0.0:8080

     房主把下面「局域网地址」发给访客，浏览器打开后进入 局域网对战 输入房间码：
       局域网  http://192.168.1.9:8080   (WLAN)
       本机    http://127.0.0.1:8080

     以下为虚拟网卡 / VPN（WSL、Hyper-V、Radmin、Tailscale 等，一般不用发给访客）：
       http://172.21.160.1:8080   (vEthernet (WSL (Hyper-V firewall)))
       http://26.212.40.62:8080   (Radmin VPN)

     健康检查  http://127.0.0.1:8080/healthz

     提示：Windows 首次运行会弹防火墙提示，请勾选「专用网络」并允许访问（见 docs/LAN.md）。
     按 Ctrl+C 停止服务器。
   ================================================================
   ```

2. **Windows 首次运行会弹防火墙提示** → 勾选 **「专用网络」** 并点「允许访问」。
   如果误点了「取消」，访客会连不上；可在「Windows 安全中心 → 防火墙和网络保护 →
   允许应用通过防火墙」里找到 **Node.js** 勾上专用网络（或执行下面「防火墙排障」）。
3. 房主自己浏览器打开 `http://127.0.0.1:8080/#/lan`，输入名字 → **创建房间**，
   页面会显示 **4 位房间码**（如 `SKSM`，已避开 `I/O/0/1` 等易混字符）。
4. 把「局域网地址」+ 房间码发给访客（微信/口头都行）。
5. 访客加入后，双方各自**选好卡组 → 点准备**，房主点「开始对战」。

## 3. 访客步骤（加入房间）

1. 浏览器打开房主给的地址，例如 `http://192.168.1.23:8080/#/lan`
   （带 `#/lan` 会直接进局域网大厅；不带也可以从首页进入）。
2. 输入自己的名字 + **房间码**（大小写不敏感）→ 点 **加入房间**。
3. 选卡组 → 点准备；等房主开始。

> 手机/平板也可以用同一地址加入（浏览器需支持 WebSocket，现代浏览器都支持）。

## 4. 端口与目录自定义

```bash
npm run lan -- --port=9000            # 换端口
npm run lan -- --dir=dist             # 指定静态目录（默认 dist）
npm run lan -- --quiet                # 只打印启动横幅与错误
PORT=8080 LAN_DIR=dist npm run lan    # 环境变量方式（Linux/macOS）
```

- 端口被占用：`EADDRINUSE` → 换端口，或找出占用进程（Windows：`netstat -ano | findstr :8080`）。
- 端口对外可达性：Windows 防火墙需放行该端口/Node.js（专用网络）。
- 服务器绑定 `0.0.0.0`（所有网卡），因此局域网内任何设备都能访问；**不要**把这个端口映射到公网。

## 5. 常见问题（FAQ）

### 访客打不开页面 / 一直在转圈

1. 先确认房主浏览器自己能开 `http://127.0.0.1:8080`（服务器是否在跑）。
2. 确认访客用的是**房主打印的局域网 IP**（不是 `127.0.0.1`！`127.0.0.1` 只指访客自己）。
3. 同一 Wi-Fi？有些路由器把 2.4G/5G 或访客网络做了隔离 → 换同一个 SSID 试试。
4. 防火墙：见下一节。

### Windows 防火墙排障（最常见）

```powershell
# 以管理员身份运行：放行 TCP 8080（专用网络）
New-NetFirewallRule -DisplayName "Fards LAN 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
```

临时的替代方案：控制面板 → Windows Defender 防火墙 → 允许应用或功能通过防火墙 → 勾选 **Node.js** 的「专用」列。

### 页面能打开，但提示「房间不存在」

- 房间码输错（4 位，大小写不敏感，但 `I/O/0/1` 不会出现，用了更易辨认的字符）。
- 房主刷新了页面 / 关掉了标签页：**房主断开 = 房间销毁**，需要重新创建房间。
- 房主服务器重启了：房间也在内存里，重启即清空。

### 提示「房间已满（每房 2 人）」

一个房间只有房主 + 1 名访客。第三人需要房主新建房间。

### 提示「协议版本不一致」

两边的页面不是同一版本构建（例如房主跑的是新 `dist`，访客打开了缓存的旧页面）。
→ 让访客 **强制刷新**（Ctrl+F5），或房主重新 `npm run build` 后再刷新双方页面。

### 同一 Wi-Fi 但不同子网 / VPN

- 路由器开了「AP 隔离 / 客户端隔离」→ 设备之间互相不可见，需在路由器里关闭。
- 公司/校园网常做客户端隔离 → 换手机热点测试（房主开热点，访客连热点）。
- 开了 VPN（尤其是全局代理/虚拟网卡）→ 关掉 VPN 再试；或让访客访问 VPN 所在网段的房主 IP。

### 对局中途卡住 / 断线

- 心跳每 20s 一次；断线 30s 内会被服务器清理，另一方会收到「对手已离开」。
- 刷新页面会断开当前连接（房间销毁），需要重新建房。
- 网络抖动后请重新建房——目前不支持断线重连（房间是内存态）。

### 服务器起来后访客连上但一会儿就掉

检查是否被杀软/防火墙做了「空闲连接」拦截；`npm run lan -- --quiet` 观察是否有 `连接 cX 断开` 日志。

## 6. 安全提示（请务必阅读）

- 本服务器**只应运行在可信局域网**：没有账号体系、没有鉴权、消息是**明文 JSON**（`ws://` 非 `wss://`）。
- **不要把端口暴露到公网**（不要做端口映射/内网穿透/`ngrok` 之类），也建议只在家庭/测试环境使用。
- 房间码只有 4 位（约 100 万组合），且**任何人知道房间码即可加入**——不要把房间码发到公开群。
- 服务器不落盘任何对局数据；卡组/对局只在两台浏览器内存里。
- 如发现异常连接，直接 `Ctrl+C` 停服即可（所有连接会收到 1001 关闭码）。

## 7. 服务器实现要点（开发者）

| 文件 | 作用 |
|---|---|
| `server/lan-server.mjs` | HTTP 静态站（SPA fallback）+ `/ws` + `/healthz`；命令行参数、房间表、限流、心跳、空闲回收、SIGINT 优雅关闭 |
| `server/lib/ws-server.mjs` | WebSocket 服务端封装：优先用 `ws` 包，未安装时回退到内置 RFC6455 子集实现（文本帧/分片/掩码/ping-pong/close/背压/256KB 上限） |
| `src/net/protocol.ts` | 前后端共享的消息类型与 `LAN_PROTOCOL_VERSION`（服务器侧常量与此对齐） |
| `src/net/lanSession.ts` | 浏览器端会话（UI/battleStore 用） |
| `scripts/test-lan.mjs` | 自包含 e2e：起服务 → 建房/加入/互发消息/大消息/限流/断线清理，28 项断言 |

**协议要点**（详见 `src/net/protocol.ts`）：

- 客户端 → 服务器：`create` / `join` / `relay` / `leave` / `ping`
- 服务器 → 客户端：`welcome` / `room` / `peerJoin` / `peerLeave` / `relay` / `pong` / `error`
- 错误码：`bad_message` / `room_not_found` / `room_full` / `already_in_room` / `not_in_room` /
  `protocol_mismatch` / `rate_limited` / `internal`
- 对端消息经服务器 `relay` 原样转发（`hello` / `deckCheck` / `ready` / `start` / `sync` / `command` / `choice` / `leave` / `toast`），服务器**不解析、不保存**。

**健壮性参数**（`server/lan-server.mjs` 顶部/参数）：

| 项 | 值 |
|---|---|
| 消息大小上限 | 256KB（超出 → `bad_message`） |
| 单连接限流 | 30 条/秒（超出 → `rate_limited`，每秒重置） |
| 服务端心跳 | 30s 一次 WebSocket ping；连续 3 个周期无任何回应 → 断开 |
| 房间空闲回收 | 30 分钟无消息 → 房间销毁，双方收到 `peerLeave` |
| 优雅关闭 | `Ctrl+C`/SIGINT → 所有连接 1001 关闭，进程退出 |

**自测**：

```bash
npm run lan:test                 # 或在项目根：node scripts/test-lan.mjs
node scripts/test-lan.mjs --verbose          # 打印每条消息
node scripts/test-lan.mjs --url=http://192.168.1.23:8080   # 测已在跑的服务器
```

## 8. 已知限制

- 每房固定 2 人（房主 + 访客），不支持旁观/多人。
- 房间在内存里，服务器重启/房主刷新即失效；**不支持断线重连**。
- 无鉴权、无 TLS；不适合公网或不可信网络。
- 访客的卡组校验由房主侧执行（`deckCheck`），服务器不校验规则。
