数据源：`GET https://1939.kardsdecker.com/api/v1/cards?limit=50&page=1..33`
抓取时间：2026-11-07　全量 **1646 张**（`meta.total = 1646`，33 页 × 50 = 1650，末页 46 张）
原始数据落地：`docs/_cards.json`（1.08 MB）、`docs/_pages/p01..p33.json`

统计方法：PowerShell `Group-Object` 对 `attributes[]` 展开计数；`type`/`rarity`/`set`/`pool`/`faction` 同理。

**机制解释来源优先级**：卡牌 API `[D]` > 实战卡组 `[K]` > 官方文案 `[S]` > 规则手册 `[Z]` > wiki `[W]` > 同人实现 `[F]`。
`[Z]` = 知乎《kards 规则与全部卡牌的描述》离线页；其 5 条可被 API 证伪的断言**全部命中**，故机制性陈述按「高」采纳；**卡面描述一律以 API 为准**。

### 1.2 官方分类：**「对战词条」只有 7 个**
规则手册（知乎《kards 规则与全部卡牌的描述》，下称 **[Z]**）原文：「**对战词条：伏击、闪击、奋战、守护、重甲、冲击和烟幕**」。
→ 即 `ambush` / `blitz` / `fury` / `guard` / `heavyArmor*` / `shock` / `smokescreen` 共 **7 类**。
其余（`alpine` 山地、`pincer` 钳击、`mobilize` 动员、`intel*` 情报、`covert` 隐蔽、`salvage` 收缴、`bond` 协力、老兵）也是词条，但**不属于「对战词条」**。`[Z]` 并说明「词条在卡面上单独列出，无需重复描述效果」。

> **[Z] 可信度已验证 5/5**：其对 API 完全可测的 5 条断言全部命中 —— 副国无金卡、盟国不能带金卡、苏联/日本无反制、步兵/炮兵无重甲、美国无守护且德国守护极少。详见 `RULES_SPEC.md` §0.1。

### 2.13 `covert` ｜ 隐蔽 ｜ 11 张 ｜ 高

## 3. 老兵（Veteran）配对标记

`attributes` 中还有 88 个「形如 `BecomesVeteran:<card_id>` / `VeteranOf:<card_id>`」的一次性标记，构成 **44 组**升阶对：

- `BecomesVeteran:102_grenadier_vet` 出现在 `102_grenadier` 上 → 底版；`VeteranOf:102_grenadier` 出现在 `102_grenadier_vet` 上 → 老兵版。**44 / 44 完全配对**。
- 触发条件写在卡面，至少有 5 类：
  | 条件句式 | 样例 |
  |---|---|
  | 「行动后，升为老兵」 | `102_grenadier` |
  | 「友方部署坦克时，升为老兵」 | `14_panzergrenadier` |
  | 「友方单位累计行动三次后，升为老兵」 | `182_landwehr` |
  | 「若有友方『第 35 掷弹兵团』，升为老兵」 | `119_grenadier` |
  | 「本单位冲击后，升为老兵」 | `matilda_mk_iv` |
- 升阶 = **整卡替换**（换攻防、换效果），**重置费用、攻击力、防御力**（[Z]）。不可逆。
- **老兵牌属衍生卡**：`[D]` 验证 44 张 `VeteranOf:` 卡**全部 `is_derived=true` / `pool=derived`** → **不可构筑**；而 44 张底版（`BecomesVeteran:`）是正常可收集卡（active 29 / reserve 15）。
- **被抑制时会变回原形态**（[Z]）。
- **升阶当回合的行动限制**：若本回合已行动过（坦克为已攻击过）且**没有奋战**，则**不能再行动**——**即使老兵形态拥有闪击也不行**（[Z]）。
- 老兵稀有度与底版相同（[Z]）。

### 4.1 重要结论：**没有海军兵种类型**，但有「海军」标签
`type` 取值中**不存在** `destroyer` / `battleship` / `submarine` / `carrier` / `naval`。
海军只以两种非 `type` 形式存在：
1. **扩展包主题**：`set=NavalWarfare`（海战）106 张（type 分布：order 43、infantry 40、fighter 12、bomber 5、tank 3、countermeasure 3）。
2. **「海军」标签**：`[Z]` 说明海战赛季「新标签：海军（以前的海军卡也在这赛季被贴了标签）」。
**海军的判定规则（`[Z]` 明确给出，很重要）**：
> 名称格式为「**字母 + xx 号**」或**纯字母 + 数字的舰艇/潜艇**才是海军。**名称里带「海军」的并不是海军**（例如「海军力量」）。

→ 复刻时**不要**虚构驱逐舰/战列舰类型；`is_naval(card)` 应用**命名正则 + 显式标签表**实现（如 `^[A-Za-z]{1,4}[\s-].*号$`、`^U-\d+`）。
→ 卡面「开发 1 张英国海军牌」等效果依赖此标签。

### 6.1 非 attributes 的机制词条（`[Z]` 补充，均为「高」置信度）
这些机制**不出现在 `attributes` 字段中**，但卡面会以「关键词：」句式使用，实现时需要独立建模。

| 机制 | 语义 | 类别 |
|---|---|---|
| **部署** Deploy | **仅「通过部署（从手牌支付费用打出）」进场时触发**；经「加入战场」「返回战场」「转换」进场**不触发** | 触发 |

| **抑制** Pin | **失去所有关键词和效果**，并**重置攻击力/最大防御力/行动花费**为原值；**不会**移除压制/被收缴/被抑制/被控制 | 状态 |
| **隐蔽 / 揭示** | 见 §2.13 | 状态 |
| **被收缴** | 与收缴者**同国**、属性 **1/1**、**保留原单位所有效果** | 状态 |
| **控制** | 接管控制权；**除非是前线唯一单位，否则移至新控制者支援阵线** | 状态 |
| **免疫** Immune | 单位或总部**不受到伤害** | 状态 |
| **倒计时** | 倒计时结束后，单位触发一个事件 | 计时 |
| **转换** Convert | 把一张牌变成另一张牌；**伤害、花费和其他效果全部重置**为新牌 | 变换 |
